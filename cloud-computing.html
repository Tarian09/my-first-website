Introduction to Cloud Computing

Welcome to my CC6004NU Network and Cloud Security workshop. This page covers the main concepts of cloud computing, its characteristics, service models, deployment models and security considerations.

1. Definition of Cloud Computing

Cloud computing is the delivery of computing services over the internet. These services include servers, storage, databases, networking and software. Organisations can access computing resources when needed without having to own and maintain all the physical infrastructure themselves.

For example, an organisation can host its applications on Microsoft Azure instead of purchasing and managing its own physical servers.

Essential Characteristics

  • On-demand self-service: Users can provision computing resources when needed.
  • Broad network access: Services can be accessed through a network using different devices.
  • Resource pooling: Providers share computing resources between customers while maintaining logical separation.
  • Rapid elasticity: Resources can be increased or reduced according to demand.
  • Measured service: Resource usage is monitored and can be used for reporting and billing.

Cloud Service Models

Infrastructure as a Service (IaaS): Provides virtual machines, storage and networking. Customers typically manage their operating systems and applications.

Platform as a Service (PaaS): Provides a managed platform for developing, testing and running applications.

Software as a Service (SaaS): Provides ready-to-use software over the internet, usually through a web browser. Microsoft 365 is one example.

2. Essential Characteristics of Cloud Computing

The five essential characteristics distinguish cloud computing from traditional IT infrastructure. They allow organisations to access resources flexibly and manage their computing needs more efficiently.

For example, rapid elasticity allows an online retailer to increase its computing capacity during a busy shopping period and reduce it when demand falls. Measured service can help the organisation monitor resource usage and manage costs.

From a security perspective, organisations must also manage access permissions, monitor their environments and ensure that cloud resources are configured correctly.

3. Cloud Deployment Models

Public Cloud

Public cloud services are provided over the internet using infrastructure operated by a cloud provider. Examples include Microsoft Azure, Amazon Web Services and Google Cloud.

Public cloud offers scalability and reduces the need for organisations to purchase physical infrastructure. However, customers must configure and manage their security controls appropriately.

Private Cloud

A private cloud is dedicated to one organisation. It can be hosted within the organisation's own data centre or by an external provider.

It can offer greater control over the environment, but building and maintaining it may require significant resources and technical expertise.

Community Cloud

A community cloud is designed for organisations that share common requirements, such as security, compliance or a common mission.

Participating organisations can share resources, but they need clear agreements about governance, costs and security responsibilities.

Hybrid Cloud

A hybrid cloud connects two or more distinct cloud infrastructures to support the movement or management of data and applications between environments.

For example, an organisation might keep certain sensitive workloads in a private environment while using public cloud services for other applications. Security policies must be managed consistently across the connected environments.

4. Cloud Computing Reference Architecture

The Cloud Computing Reference Architecture describes the main roles and components involved in providing and using cloud services.

The NIST reference architecture identifies five actors:

  • Cloud consumer: The person or organisation using cloud services.
  • Cloud provider: The organisation offering cloud services.
  • Cloud broker: An intermediary that helps manage or combine cloud services.
  • Cloud auditor: An independent party that assesses cloud services, security controls or compliance.
  • Cloud carrier: The network provider that connects users to cloud services.

This architecture helps organisations understand the different responsibilities involved in cloud computing. For example, a provider may secure the physical data centre, while the customer must configure user permissions correctly.

5. Comparison of Cloud Service Providers

Different cloud providers offer computing, storage, networking, database and security services. Their strengths and deployment options vary according to the products and configurations available.

Provider Example Services Key Strengths
Microsoft Azure Virtual Machines, Azure Storage, Azure SQL Microsoft integration and hybrid cloud
Amazon Web Services EC2, S3, RDS Scalability and a broad service portfolio
Oracle Cloud Infrastructure Compute, storage and Oracle databases Oracle database and enterprise workloads
IBM Cloud Virtual servers, Kubernetes and databases Hybrid cloud and enterprise solutions
Google Cloud Compute Engine, Cloud Storage, BigQuery Analytics, AI and container services
Alibaba Cloud Elastic Compute Service and Object Storage Cloud services for businesses, particularly in Asia

All six providers offer public cloud services. Their private, hybrid and dedicated infrastructure options differ. Organisations should compare security, cost, compliance, technical requirements and integration with existing systems before choosing a provider.

For example, Azure may suit an organisation already using Microsoft 365 and Microsoft Entra ID, while Oracle Cloud Infrastructure may be suitable for workloads that depend heavily on Oracle databases.

6. Organisations Using Cloud Providers

Organisations use cloud services to support applications, store information and provide services to their customers. The following are examples of publicly reported relationships between organisations and cloud providers.

  • Netflix and AWS: Netflix uses AWS infrastructure to support its streaming service.
  • Zoom and Oracle Cloud: Oracle announced that Zoom selected Oracle Cloud Infrastructure to support its video communications service.
  • Spotify and Google Cloud: Spotify has publicly discussed its use of Google Cloud infrastructure.
  • Accenture and Microsoft: The organisations work together on enterprise cloud solutions and Azure services.
  • Vodafone and IBM: The organisations have worked together on enterprise technology and cloud initiatives.
  • Lazada and Alibaba Cloud: Lazada has been associated with Alibaba Cloud services supporting its e-commerce operations.

These examples illustrate how cloud services can support different business requirements. However, a relationship with a cloud provider does not necessarily mean that an organisation uses every deployment model offered by that provider.

7. UK Government Cloud Compared with EU Countries

The UK government has promoted cloud adoption through its Cloud First policy, which encourages public-sector organisations to consider cloud solutions when procuring IT services. G-Cloud is one of the procurement arrangements used by public-sector organisations to obtain cloud services.

United Kingdom

The UK approach encourages departments to consider cloud services while taking account of security, operational needs and other requirements.

Germany

German public-sector cloud decisions place importance on data protection, digital sovereignty and security requirements.

France

France has developed trusted-cloud approaches that give particular attention to national control and the protection of sensitive information.

Estonia

Estonia is known for its digital public services and digital-government infrastructure. It provides a useful comparison when discussing the use of technology in government services.

Netherlands

Dutch public-sector organisations also need to consider privacy, information security and procurement requirements when adopting cloud services.

Security Considerations

Governments need to consider data protection, data sovereignty, access control, incident response, business continuity and supplier risk when selecting cloud services.

In my view, the deployment model should depend on the sensitivity of the information, legal requirements, resilience needs and the level of control required. Governments need to balance the benefits of cloud computing with their responsibility to protect public information.

A detailed comparison should also be supported by the ENISA publications listed in the Week 1 workshop materials and current government sources.

Conclusion

Cloud computing allows organisations to access flexible computing resources without having to maintain all the underlying physical infrastructure. However, choosing a cloud service also requires careful consideration of security, compliance, cost and operational requirements.
